## Findings and repair plan

### QA-01 — misleading Undo assignment instructions

Reproduction: assign `QA-20261017-IMMEDIATE`, confirm level 1, open Undo.
The workflow retains assignments until completion. The dialog promises to end
any assignment, and the success toast instructs the user to assign again.
Actual result: Undo returns to Assigned with the existing assignee, as configured.

Plan: remove unconditional assignment claims from the confirmation and toast;
keep the server policy authoritative. Verify both retention modes and the
persisted assignment, plus frontend regression tests.

Status: fixed and verified in browser/API and automated regression tests.

### QA-02 — duplicate count refresh after mutations

Reproduction observed while a grid filter was loading: confirm level 1 successfully.
The UI shows both “Message confirmed” and “Changes saved, but the displayed data
could not be refreshed”, then renders the updated data. Mutation invalidation
refreshes counts while its grid callback also explicitly refetches those counts;
competing requests cancel one another. The API log shows cancelled count reads.

Plan: use a grid-only callback for mutation refreshes and retain count refetch
for the manual Refresh button. Keep warnings for actual failures. Test that a
mutation callback refreshes the grid without starting a second count request.

Status: fixed and verified in browser/API and automated regression tests.

### QA-03 — inaccessible ViewOnly messages reveal their state through mutation errors

Reproduction: Amelia cannot read a ViewOnly message in another branch (404), but
POST assign returns 409 with “View-only messages cannot be changed” rather than
the same forbidden response as other inaccessible messages. The domain guard ran
before the scoped visibility check.

Plan: check visibility before reporting ViewOnly mutation restrictions. Keep
409 for visible ViewOnly messages and administrators; return 403 for inaccessible
ones. Add SQL authorization regression coverage and repeat negative HTTP checks.

Status: fixed and verified in browser/API and automated regression tests.
